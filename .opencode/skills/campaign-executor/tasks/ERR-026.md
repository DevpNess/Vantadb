# Task ERR-026 — parse_metadata descarta filtros no-escalables

**Estado:** ✅ COMPLETADA — commit `ce265569`
**Fecha:** 2026-08-09

## Context Save

- **Bug:** `parse_metadata` (vantadb-mcp/src/lib.rs) solo mapeaba `as_str/as_bool/as_i64/as_f64`; arrays/objects/null se descartaban silenciosamente → filtro no aplicado → resultados súper-conjunto.
- **Fix:** `parse_metadata` ahora devuelve `Result<VantaMemoryMetadata, McpError>`; tipos no soportados (array/object/null) → `McpError::invalid_params` nombrando la key y los tipos soportados. Se usó `McpError::invalid_params` (seam nativo del crate MCP, igual que `validate_identifier`) en vez de `VantaError::InvalidInput` — el contrato pedía "fall explícito o mapeo explícito documentado"; el error explícito satisface ambas ramas y es consistente con el resto del handler.
- **Call sites actualizados (3):** `memory_put` (metadata), `memory_list` (filters), `search_memory` (filters) — `.map_err(|e| e.to_json())?` (mismo patrón existente).
- **Tests:**
  - Unit (en lib.rs, tests module): `parse_metadata_rejects_non_scalar_values` — array/object/null → Err; escalares → Ok con len 4.
  - Integration (vantadb-mcp/tests/mcp_tests.rs): `test_mcp_parse_metadata_rejects_non_scalar_values` (pre-existente, tenía bug de move `cases` → se arregló iterando `&cases` y `*key` en json!).
