## Investigation Notes
- **Capacidad real del core (fuente: codegraph + código):** `VantaValue` (src/sdk/types.rs:57) tiene variantes `String/Int/Float/Bool/DateTime/ListString/ListInt/ListFloat/ListBool/ListDateTime/Null`. `VantaMemoryMetadata = BTreeMap<String, VantaValue>`. El filtrado de metadata usa equality estricto `record.metadata.get(key) == Some(expected)` (src/sdk/serialization/mod.rs:411-418) y `to_index_values()` aplana listas para indexado (types.rs:85-98).
- **Paridad con Python:** `vantadb-python/src/convert.rs:72-183` (`py_any_to_value`) delega: None → Null, list vacía → ListString(vec![]), list homogénea → List* según primer elemento (i64 antes que bool por subclase de int), dict → error "Unsupported field value".
- **Decisión (source-driven):** el core SÍ puede filtrar arrays/null → el MCP DEBE delegarlos. El fix previo ce265569 (commit `ce265569`, 2026-08-09) rechazó arrays/null/objects con error, sin verificar la capacidad del core. Este task lo corrige: delegar arrays homogéneos y null; rechazar solo objetos y arrays mixtos (no representables).
- **Límite JSON:** JSON no tiene tipo datetime nativo → strings RFC3339 quedan como `String` (igual que hoy); no se introduce `DateTime` desde MCP.
