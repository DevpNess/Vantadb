## Contexto

- Finding: `vantadb-python/src/convert.rs` cache LRU con evicción O(n) `min_by_key`.
- Verificado en git history: `cee4ffbf` ya agregó tick-based tracking (u64) para `get`/`put`,
  pero la **evicción en `put` sigue siendo O(n)** con `min_by_key` (líneas 59-63 actuales),
  y el propio comentario lo admite: "Eviction is O(n) (`min_by_key` scan)". **NO es STALE.**
- Crate `lru` ya está en el workspace: `lru = "0.16"` directa en Cargo.toml raíz (vantadb),
  usada en `src/cli_server.rs:14,223-234`. Lockfile resuelve lru 0.16.4 (lru 0.12.5 es
  transitiva de tantivy — NO usarla). Escalera ponytail rung 5: dependency ya instalada → usar.
- API verificada en docs.rs (lru 0.16.4): `new(NonZeroUsize)`, `get(&mut self, &Q) -> Option<&V>`
  (mueve al head, O(1)), `put(&mut self, K, V) -> Option<V>` (evicción O(1) automática).
  Source: https://docs.rs/lru/0.16.4/lru/struct.LruCache.html
