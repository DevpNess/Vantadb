# DRV-004: List pagination — avoid loading ALL records into memory

## Descripción

`list()` en `src/sdk/api.rs:258-277` llama a `records_for_namespace()` que ejecuta `engine.get_many(&unique_ids)` — **carga TODOS los nodos de un namespace en memoria** para después hacer slice. Con 100K+ registros esto produce OOM.

## Análisis

**Código actual:**
1. `indexed_ids_by_namespace()` → `Vec<u128>` (~1.6MB para 100K — **aceptable**)
2. `engine.get_many(&unique_ids)` → carga **todos** los nodos → OOM
3. Filtra, ordena por (key, node_id), devuelve todo
4. `list()` hace slice sobre el resultado completo

**Root cause:** `get_many()` con 100K+ IDs es inviable. La solución es paginar las peticiones de fetch.

## Approach

**ID-based pagination:** iterar sobre `unique_ids` (solo vectores de u128), hacer `get_many()` solo para el window `[cursor..cursor+limit]`.

Esto cambia el orden: de key-sorted a namespace-index-order (estable por inserción/ID). Aceptable para list paginada — el cursor es opaco para el consumidor.

## Cambios necesarios

### 1. Modificar `list()` en `src/sdk/api.rs`

Reemplazar el cuerpo actual:

```rust
// ANTES: carga todo en memoria
let records = self.records_for_namespace(namespace, &options.filters)?;
let start = options.cursor.unwrap_or(0).min(records.len());
let limit = options.limit.max(1);
let end = start.saturating_add(limit).min(records.len());
let next_cursor = (end < records.len()).then_some(end);
Ok(VantaMemoryListPage { records: records[start..end].to_vec(), next_cursor })
```

```rust
// DESPUÉS: paginación directa sobre IDs (sin cargar todo)
let engine = self.engine_handle()?;
let (candidate_ids, has_index_entries) = if let Some((field, value)) = options.filters.iter().next()
{
    self.indexed_ids_by_filter(&engine, namespace, field, value)?
} else {
    self.indexed_ids_by_namespace(&engine, namespace)?
};

let limit = options.limit.max(1);
let cursor = options.cursor.unwrap_or(0);

// Deduplicar IDs
let mut seen = BTreeSet::new();
let unique_ids: Vec<u128> = candidate_ids.into_iter().filter(|id| seen.insert(*id)).collect();

// Fetch solo el window de IDs
let window_ids: Vec<u128> = unique_ids.iter().skip(cursor).take(limit).copied().collect();
let mut records: Vec<VantaMemoryRecord> = Vec::with_capacity(window_ids.len());
for node in engine.get_many(&window_ids)? {
    if let Some(record) = memory_record_from_node(&node) {
        if record.namespace == namespace && matches_memory_filters(&record, &options.filters) {
            records.push(record);
        }
    }
}

// Fallback: scan completo si no hay índice (pero paginado)
if records.is_empty() && !has_index_entries {
    crate::metrics::record_derived_full_scan_fallback();
    // Scan but skip to cursor position and take limit
    let mut skipped = 0usize;
    for node in engine.scan_nodes()? {
        if let Some(record) = memory_record_from_node(&node) {
            if record.namespace == namespace && matches_memory_filters(&record, &options.filters) {
                if skipped < cursor {
                    skipped += 1;
                    continue;
                }
                records.push(record);
                if records.len() >= limit {
                    break;
                }
            }
        }
    }
}

let end_cursor = cursor.saturating_add(limit);
let next_cursor = (end_cursor < unique_ids.len()).then_some(end_cursor);
Ok(VantaMemoryListPage { records, next_cursor })
```

### 2. `use` additions needed

Agregar al tope de `api.rs`:
- `use super::serialization::impl_export::{indexed_ids_by_namespace, indexed_ids_by_filter, memory_record_from_node, matches_memory_filters};` — verificar si ya están (chequear imports actuales)

Actually, estas funciones son `pub(crate)` o `fn` del `impl VantaEmbedded` block. Ya se llaman como `self.indexed_ids_by_namespace(...)` y `self.indexed_ids_by_filter(...)` — son métodos de `VantaEmbedded` definidos en `impl_export.rs`. La función `memory_record_from_node` y `matches_memory_filters` son free functions en `serialization.rs` ya importadas vía `use super::serialization::{memory_record_from_node, matches_memory_filters}`.

### 3. Update docstring

Actualizar docstring de `list()` para reflejar:
- Que ahora pagea por IDs directamente (namespace index order)
- Ya no carga todos los records en memoria
