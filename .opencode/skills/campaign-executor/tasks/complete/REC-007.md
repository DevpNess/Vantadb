# REC-007: WAL Compaction + Vacuum CLI Commands

**Source:** docs/plans/2026-07-28-recovery-plan.md (Fase 2)

**Effort:** 🟢 ~1-2h

## Description

Agregar subcomandos CLI `vanta-cli wal compact` y `vanta-cli wal vacuum`. Ambos ya existen como métodos en el SDK (`VantaEmbedded::compact_wal()`, `VantaEmbedded::vacuum()`) pero no están expuestos en CLI.

**Hallazgo:** 🟠 Hallazgo 6 de auditoría 2026-07-28 — funciones existen en engine y SDK, solo falta binding CLI.

## Spec

```
vanta-cli wal compact    # Llama a VantaEmbedded::compact_wal()
vanta-cli wal vacuum     # Llama a VantaEmbedded::vacuum()
```

## Acceptance Criteria

- [ ] `vanta-cli wal compact` implementado y funcional
- [ ] `vanta-cli wal vacuum` implementado y funcional
- [ ] Ambos commands abren DB (read-write), ejecutan operación, cierran DB
- [ ] `vanta-cli wal --help` documenta ambos subcomandos
- [ ] `vacuum()` muestra mensaje de progreso ("Vacuuming..." / "Done.") porque puede tardar

## Files

- `src/cli.rs` — nuevo subcommand enum `Wal(WalCommand)` con subcomandos `Compact` / `Vacuum`
- `src/cli_handlers/wal.rs` — nuevo módulo con handlers `cmd_wal_compact()` / `cmd_wal_vacuum()`
- `src/cli_handlers/mod.rs` — agregar `pub mod wal;` + `pub use wal::*;`
- `src/bin/vanta-cli.rs` — agregar dispatch `Commands::Wal(cmd) => match cmd { ... }`

## Design Decisions

- **Nuevo archivo `wal.rs`** (no mezclar en `db.rs`) — operaciones de mantenimiento WAL merecen su propio módulo.
- Mostrar "Vacuuming..." → "Done." por si la DB es grande y tarda.
- Usar patrón `open_embedded(db_path, false)` (read-write, no read-only).
