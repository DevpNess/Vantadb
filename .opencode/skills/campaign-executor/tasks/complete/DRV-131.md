## Descripción

VantaDB actualmente solo tiene 2 tipos de índice vectorial:
- **HNSW** (`src/index/graph.rs`) — graph-based ANN, latencia más baja, alta recall
- **Flat** (`src/index/flat.rs`) — brute-force O(n) scan, usado como fallback cuando `nodes < flat_threshold` (default 10000)

Quiver (referencia de la industria) tiene 8 tipos: HNSW, DiskVamana/DiskANN, IVFFlat, IVF+PQ, ScalarQuantizer, BinaryQuantizer, etc.

Esta tarea agrega **IVF (Inverted File Index)** como el primer nuevo tipo de índice, que ofrece el tradeoff de build rápido + recall predecible + RAM controlable.

## Arquitectura Propuesta

### 2. IndexConfig trait mínimo (en `src/index/mod.rs` o archivo nuevo)

No un trait complejo — solo lo que `CPIndex` necesita configurar:
- `HnswConfig` ya existe y se usa
- `IvfConfig` nuevo: `nlist`, `nprobe`, `distance_metric`

### 3. CPIndex refactor mínimo

`CPIndex` ya es el struct de índice. Las opciones:

- **Opción A (ponytail)**: Field `index_type: IndexType` en `HnswConfig` (o nuevo struct `IndexConfig` enum). `search_nearest` switchea según tipo. Si `IndexType::Ivf`, rebota a `ivf_search()`.

  **Problema**: `CPIndex` está nombrado como "CP" (Cosine/Product?), sus fields `nodes: DashMap<u128, HnswNode>` están tipados como HNSW. IVF necesita estructura diferente (centroids + listas invertidas).

- **Opción B (mínimo viable)**: Crear `IvfIndex` como struct separado, sin tocar CPIndex. En `search_nearest`, si `self.config.index_type == IndexType::Ivf`, reconstruir IVF desde los nodos HNSW existentes (esquema "reconstruir en cada search"). **Ponytail: no tocar CPIndex, agregar wrapper.**

- **Opción C (elegida — balanceado)**: `IvfIndex` struct separado con su propio search. Registrar en StorageEngine un `Option<IvfIndex>` que se construye/built explícitamente (no en cada search). `search_nearest` delega según `index_type`.

### 4. IVF implementation

IVF (Inverted File Index):
- **Build**: K-means clustering de los vectores → `nlist` centroides. Asignar cada vector al centroide más cercano → lista invertida.
- **Search**: Computar distancia query → nprobe centroides más cercanos. Hacer flat search dentro de las listas invertidas de esos centroides. Re-rankear resultados combinados.
- **K-means**: Implementación simple con Forgy initialization + Lloyd iteration. Max 20 iteraciones o convergencia < 1e-4.
- **Serialización**: `IvfIndex` debe ser serializable (postcard o bincode).

### 5. Integración con el pipeline existente

| Componente | Cambio |
