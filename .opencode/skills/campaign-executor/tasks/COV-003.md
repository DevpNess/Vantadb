# COV-003 — Rust tests del binario CLI

## Estado: ✅ COMPLETED

## Contrato original
`cargo nextest run -p vantadb --features cli --profile audit --build-jobs 2` pasa
→ **Contrato defectuoso**: el profile `audit` hereda el default-filter de nextest que EXCLUYE `binary(cli_tests)` (.config/nextest.toml). El contrato literal nunca corría los tests CLI. Verificación real corregida: `cargo test -p vantadb --features cli --test cli_tests`.

## Resultado real
- **67/68 tests CLI pasan** (996 líneas, 68 tests)
- 1 fallo restante = **ERR-010 pre-existente** (`Timeout acquire insert_lock in flush (ERR-010 checkpoint)`, `test_cmd_rebuild_index_empty`) — confirmado en HEAD limpio vía `git stash` (también bloquea el profile full audit y 2 tests Python)
- `wal_sharded` unit tests: 30/30 ✅ (incluye test nuevo de ERR-050)

## Hallazgos que destapó (3 bugs reales, 2 commits)
1. **ERR-050** — `ShardedWal::new` reseteaba `next_shard=0` en cada open; WAL multi-shard (`wal_shards=4` default) acumulaba writes en shard 0 → `[2,0,0,0]` → ERR-011 abortaba recovery en el 3er open read-write. **El CLI real (`put`→`put`→`delete`) fallaba.** Fix `c773ee9c`: `next_shard = durable_records % num_shards` al abrir. Test: `test_reopen_resumes_round_robin_position`.
2. **Seed sin flush** — helpers `seed_embedded*` usaban `VantaEmbedded::put` sin `flush`; un reopen **read-only** no rejuega WAL (init.rs:419) → records "desaparecían" del veredicto. Fix `be3a785c`: `db.flush()` en ambos helpers.
3. **crc32c crash en backup** — `file_crc32c` → `compute_crc32c(&[])` panickea UB check en crc32c-0.5.0 (`from_raw_parts<u64>` con slice vacío, exit 0xc0000409) al leer WAL shards vacíos. Fix `be3a785c`: guard `is_empty() → return 0` en `src/wal.rs`.

## Nota operativa
- En Windows el run completo de cli_tests puede crashear con STATUS_STACK_BUFFER_OVERRUN (stack de hilos). Workaround: `$env:RUST_MIN_STACK="16777216"` + `--test-threads=4`.
