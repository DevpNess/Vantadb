## Descripción

`batch_insert_with_opts` llamaba `self.get(n.id)` por cada nodo en el rayon path (10k batch = 10k read-paths completos): active-txn lock, cache **write** lock, KV metadata read, HNSW lookup, vstore mmap vector read + clone descartado. Optimizar el existing-check.

## Solución

Nuevo probe `existing_for_batch(id)` en `src/storage/engine/ops.rs` que devuelve solo `relational` + `edges` (todo lo que necesita el bookkeeping de cardinality/edge/scalar index):

1. **Read-your-writes**: chequea active txn buffer primero (paridad con `get()`).
2. **Cache**: `volatile_cache.read()` compartido — sin write lock, sin bookkeeping de hits (probe, no read).
3. **Backend**: solo lee el blob de metadata KV (`deserialize_node_payload`), nunca el vector en vstore.

Se reemplazó `self.get(n.id).unwrap_or(None)` por `self.existing_for_batch(n.id)` en el rayon path (`par_iter`, mantiene paralelismo) y en el non-rayon path (`if let Some(existing_node)`).

`skip_existing_check` ya existía en `BatchInsertOptions` y es usado por bulk loaders (`src/sdk/api.rs:277`, benches) — se mantiene como opción para inserts puros; el default conserva el check porque `batch_insert` público es upsert-safe.
