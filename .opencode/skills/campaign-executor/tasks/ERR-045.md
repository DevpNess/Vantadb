# ERR-045 — 🟡 `get_neighbors` clona la lista por nodo → O(N×M) allocs durante compactación BFS

> ID: ERR-045 · Área: `src/index/` · Tipo: performance · Esfuerzo: 🟡 · Rama: `develop`
> Estado: ⬜ PENDING

## Contexto

`HnswNeighborIndex::get_neighbors` (src/index/neighbor_index.rs:75) devuelve `Option<NeighborVec>`
clonando la lista de vecinos. Durante la compactación BFS (`serialization_order` en graph.rs:1042,
usado por `serialize_to_bytes` en serialize.rs:100), cada nodo visita cada layer y clona su lista →
O(N×M) allocs.

`get_neighbors_ref` (neighbor_index.rs:84) YA EXISTE (agregado en un intento previo de ERR-045) y
devuelve `Option<dashmap::mapref::one::Ref<...>>` sin clonar. Ya lo usan 5 callers
(stats.rs, cache_warmer.rs, core.rs:207, archive.rs). El trabajo restante: convertir el caller
BFS de compactación que todavía clona.

**Veredicto:** El fix mínimo es convertir el BFS de `serialization_order` (graph.rs:1058-1061) a
`get_neighbors_ref`. Comportamiento idéntico: mismo BFS (cola FIFO + seen-set), misma semántica de
lista vacía/ausente. Elimina N×M clones del hot path de compactación. No requiere tocar la API de
neighbor_index ni otros callers. `for_each` (neighbor_index.rs:297) clona, pero su caller
(`repair_orphan_links`) es mantenimiento, no compactación — fuera de scope (ponytail).
