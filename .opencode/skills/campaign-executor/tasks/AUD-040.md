## Contexto

- Finding: en `batch_append` (src/wal.rs:297-329), cada record se serializa con
  `postcard::to_allocvec(record)` → **1 alocación por record** (n allocs por batch).
- Fix: serializar directamente al buffer de salida reutilizable con `postcard::to_io`
  + slot de length placeholder + patch + CRC. **Cero alocaciones extra por record.**
- **API real verificada (fuente local, postcard 1.1.3):** `postcard::serialize_into` **NO existe**
  en 1.1.3 (404 en docs.rs). La función std-io es `postcard::to_io<T, W>(value, writer) -> Result<W>`
  donde `W: std::io::Write` (src/ser/mod.rs:310-317), **gated por feature `use-std`**
  (`use-std = ["serde/std", "alloc"]`, aditivo y seguro para crate std).
  Fuente: `C:\Users\Eros\.cargo\registry\src\index.crates.io-1949cf8c6b5b557f\postcard-1.1.3\`
- **Formato en disco (verificado en lector):** por record `[u32 LE len][payload postcard][u32 LE crc32c]`
  (src/wal.rs:652-671 `WalReader::next_record`, `check_record_at` :466-485, `recover_valid_records` :535-546).
  El fix preserva byte-por-byte este framing: escribe placeholder de 4 bytes, serializa payload,
  parchea los 4 bytes con len, escribe crc. `to_io` produce el MISMO payload postcard que `to_allocvec`.
- `Cargo.toml` línea 29: `postcard = { version = "1.1", features = ["alloc"] }` → agregar `"use-std"`.
  Cargo.lock NO cambia (features no afectan el lockfile).

- [x] **SECURITY** — No aplica: no toca trust boundary, input de usuario, auth, ni dependencias nuevas

- [x] **PERFORMANCE** — Aplica (hot path de serialización WAL): elimina n allocs por batch.
  Baseline estructural: antes n allocs (1 `to_allocvec` por record) + 1 `buf`; después 2 allocs totales
  (buf + 1 Vec de payload reutilizable con capacidad reservada — `clear()` conserva capacidad).
  Sin microbench numérico (tarea Baja); evidencia = test byte-identity + estructura de allocs.
  **Landmine descubierto:** crc32c-0.5.0 `util::split` panic (UB check) en sub-slices cortas (< 8 B)
  a offsets desalineados — el diseño inicial (serializar directo a `buf` + crc sobre sub-slice) lo
  disparaba (record `Delete` = payload 2 B en offset 4). Solución: payload Vec propio reutilizable
  (alloc fresco SIEMPRE 8-alineado → crc32c seguro), que además es más simple que placeholder/patch.
