## Notas de diseño

- **Segmentos honestos (Riesgo plan línea 159):** el wire NO trae `fusion_report` (VS-CORE-03 mapea solo
  `ExplanationHit`). El score del hit ES la suma RRF de ramas (`src/planner.rs:174`); con los ranks 1-based
  del wire, la contribución de cada rama se reconstruye EXACTAMENTE con `1/(RRF_K + rank)` — no se inventa
  nada. El segmento RRF solo aparece como residuo si el score excede la suma (p.ej. fuse_rrf_many con sparse).
- **Cleveland–McGill (P7):** longitud = encoding primario (el más preciso); color solo secundario (1 accent
  neón en el segmento RRF); gris escala legible si falla el color; tooltip + número = redundancia.
- **Vector-picker:** records con vector vía `listPage` (VS-CORE-01 ya devuelve `vector`); si el registro
  seleccionado en el Inspector tiene vector, es el seed inicial de la lente (P4: lente contextual).
- **Audit:** `auditEvents({namespace, limit})` y filtro client-side por `key === r.id` (el API VS-12 no filtra
  por key); si falla (audit no configurado) → hint honesto, no error duro.
- **ponytail:** sin charts lib, sin deps nuevas; barras = divs con width%. La lógica pura es autónoma
  (sin imports) para poder self-checkear con node puro.
