## Decisiones de diseño (verificadas contra docs oficiales)
- **r3f v9 + drei v10, NO v8:** el orquestador asumía React 18, pero `desktop/package.json` tiene `react ^19.1.0`. Docs oficiales (r3f.docs.pmnd.rs/getting-started/installation + GitHub pmndrs/react-three-fiber): `@react-three/fiber@8 ↔ react@18`, `@react-three/fiber@9 ↔ react@19`. v9.6.x actual; drei v10 (React 19 line).
- **Layout radial espiral por degree** (ordenados por degree desc → centro): sin force-directed (orquestador: overkill; contrato pide visor+expand, no física).
- **Labels con drei `<Html>`** (top-N por degree): troika-three-text (drei `<Text>`) carga su fuente default de un CDN remoto → falla offline en Tauri. `<Html>` es DOM, usa fuentes locales.
- **Click nodo = expand BFS** (contrato del orquestador). Inspector/openRecord NO en esta task: `node_id` (u128 string) no es reversible a key de registro sin core; GRAFO-03 (IQL console) resalta subgrafo. Deuda anotada.
- **Fade de nodos viejos:** al exceder MAX_NODES=500, evict los más viejos por inserción (Map preserva orden), nunca el nodo activo; opacidad 0.15 por 350 ms antes de remover.
- **Seed:** `list({limit:500})` → namespace con más registros → `graphDegree({namespace, limit:30})` (nodos sin aristas; el namespace vacío devuelve []).

### Step 8: Force-directed (re-feedback D5 — layout radial rechazado)
- **Archivos:** `desktop/src/components/graph/GraphScene.tsx` (simulación d3-force), `desktop/src/components/graph/GraphNode.tsx` + `GraphEdge.tsx` (posición por frame desde ref), `desktop/src/components/graph/useGraphData.ts` (revision, sin positions; radialLayout queda como fallback), `desktop/src/components/graph/GraphLens.tsx` (props), `desktop/package.json` (d3-force@3.0.0 + @types/d3-force)
- **Acción:** reemplazar layout radial estático por force-directed: `forceSimulation` con forceLink (distance 2.2, strength 0.5 — disuasión hubs), forceManyBody (strength -18, distanceMax 25 — repulsión global anti-hub-colisón), forceCenter, forceCollide (radius ∝ tamaño + 0.15 — anti-overlap). Tick manual `sim.tick()` en useFrame (frame loop controlado del contrato, fuera del render React; sin worker: 500 nodos < 1 ms/frame). Posiciones en `positionsRef` (Map mutable); GraphNode/GraphEdge leen por frame vía useFrame mutando object3D (`g.position.set` / `l.geometry.setPositions` + `computeLineDistances`) — cero re-renders durante la simulación.
- **Expansión incremental:** sync effect re-corre en cada `revision` del hook (solo cuando cambia el grafo, no en setActiveId — guard `revisionRef`); re-sync `sim.nodes()`/`linkForce.links()` + reheat `sim.alpha(0.35)`; nodos nuevos nacen en la posición del nodo expandido (`activeId`) — efecto de crecimiento, no teleport. Datum persistentes por id (`simNodesRef`) conservan x/y entre syncs.
- **prefers-reduced-motion:** `usePrefersReducedMotion()` (matchMedia nativo — drei v10 NO exporta useReducedMotion, verificado en node_modules) → fallback `radialLayout` estático sin animación.
- **Fit:** tras ~30 ticks (FIT_AFTER_TICKS) para encuadrar el layout desplegado, no el bbox puntual del primer batch; fit manual inmediato; post-reset encolado igual que antes.
- **Verify:** `npx tsc --noEmit` ✅ 0 err (fix: Line2 no expone `.points` en three-stdlib → `geometry.setPositions()`; LineSegmentsGeometry lo tiene); `npm run build` ✅ (GraphLens chunk lazy 961 kB raw / 263 kB gzip — d3-force +16 kB); `npm --prefix desktop run build` vía campaign_verify_cmd ✅
