# REV-014 — Dependabot PRs a develop (no main)

## Tipo
CI/CD / DevOps → vanta-lead (yo mismo)

## Discovery
- `dependabot.yml` tiene 4 ecosystems: cargo, npm, github-actions, docker
- **No tiene `target-branch` configurado** → Dependabot usa default branch (main)
- Backlog.md actualizado de "debe apuntar a develop" a "verificar"

## Análisis
GitHub Dependabot no soporta `target-branch` en la forma más común esperada:
- El `target-branch` solo aplica a **version updates** (patch/minor/major)
- Los **security updates** SIEMPRE van al default branch (main)
- No hay forma de hacer que dependabot mande security updates a develop

## Opciones
1. **Agregar `target-branch: develop` al dependabot.yml** — hace que los PRs de version updates vayan a develop
2. **No cambiar nada** — los PRs a main se mergean y luego se backportean a develop (más trabajo manual)
3. **Configurar auto-merge + branch rules** — los PRs de dependabot a main se auto-mergean si pasan CI

## Decisión
Opción 1 es la correcta: agregar `target-branch: develop` para los 4 ecosystems.

## Pasos atómicos
1. Verificar que develop branch existe en GitHub
2. Agregar `target-branch: develop` a cada update en dependabot.yml
3. Commit + push

## Verification
- `yamllint .github/dependabot.yml` ✅
- Dependabot preview muestra PRs apuntando a develop
- No romper security updates (van a main por defecto)
