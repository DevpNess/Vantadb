## Investigation Notes
El handler `memory_put` en `vantadb-mcp/src/handlers/tools.rs` define un schema JSON-RPC (L20-32 aprox) que NO incluye `expires_at_ms` ni `sparse_vector`. Al recibirlos, el JSON extra se descarta (serde por defecto ignora campos desconocidos) y el record se crea sin TTL ni sparse. El core (`VantaMemoryRecord`) sí soporta ambos (el SDK Python tiene `ttl_ms` y el sparse index existe en `src/sdk/serialization/impl_sparse_index.rs`).

Fix: agregar `expires_at_ms: Option<u64>` y `sparse_vector` (objeto dim→weight, NO `Vec<f32>`) al schema del tool + parsearlos al `VantaMemoryInput`. `ttl_ms` del input es relativo → convertir `expires_at_ms` absoluto con `saturating_sub(now_ms())`. **OJO:** `impl_sparse_index.rs` fue editado recientemente (pending index sync) — NO se toca (core, propiedad de Arch/Engine).

**NO romper** backward compat: los campos nuevos deben ser optional en el schema y el parseo debe tolerar ausencia.
