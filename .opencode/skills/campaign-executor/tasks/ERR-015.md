# ERR-015 — graceful shutdown con timeout antes de kill en child_process

**Estado:** ✅ COMPLETED
**Commit:** `704f2a67` — `fix(ERR-015): graceful shutdown with timeout before kill in child_process`
**Fecha:** 2026-08-10

## Problema
`request_shutdown` en `desktop/src-tauri/src/connections/child_process.rs` usaba
`kill()` (force kill on all platforms) SIEMPRE, sin señal graciosa — risco de
metadata loss en Windows (flush pendiente del storage engine del sidecar).

## Fix
Patrón graceful-shutdown en `McpSpawn::request_shutdown(grace)`:
1. **unix:** envía SIGINT (`libc::kill`, vía helper `send_graceful_stop`) — el
   sidecar MCP (`vantadb-server --mcp`, `run_stdio_server`) cierra su loop en
   SIGINT → tokio `signal::ctrl_c` → flush del storage engine.
2. Espera hasta `grace` con `tokio::time::timeout(grace, child.wait())`; si el
   child sale, return Ok.
3. **Backstop (y único path en Windows):** force-kill + reap si el child no
   terminó en `grace`.

Windows no tiene señal graciosa per-proceso entregable (doc comment cita MS
Learn: CTRL_C no se puede limitar a un process group) → degrada a kill, igual
que antes pero documentado.
