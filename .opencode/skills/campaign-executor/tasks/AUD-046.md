## Evidencia
- `memory_put` con vector 2-dim en un namespace con índice 4-dim → **aceptado silenciosamente**; `vector_count` sube; el nodo NUNCA aparece en `search_memory`/`search_semantic`
- `search_memory`/`search_semantic` SÍ validan dims cuando el índice existe → `Vector dimension mismatch: expected 4, got 3`
- Root cause: el handler de put no valida dims contra el índice existente; solo el search lo hace
- Nota: en namespace SIN índice, put con dims arbitrarias es legítimo (define el índice) — la validación debe aplicar SOLO cuando el índice ya existe

## Contrato
"`memory_put` con dims ≠ índice existente devuelve error claro `Vector dimension mismatch: expected 4, got 2`; put en namespace sin índice sigue definiendo dims; `mcp_tests` 34/34 verdes"

## Investigation Notes
La validación de dims ya existe en el path de search (probablemente en el SDK serialization o en el handler). Reutilizar ESA misma lógica en el put en lugar de duplicar. Regla: si el namespace ya tiene índice con dims D y el vector entrante tiene dims ≠ D → error. Si no hay índice → aceptar (crea el índice con esas dims).

**NO cambiar** la semántica del search ni permitir vectores mixtos en un índice existente.

### Step 1: Localizar validación de dims en search
- **Archivos:** `vantadb-mcp/src/handlers/tools.rs` (search), `src/sdk/serialization/` (validación)
- **Acción:** codegraph_explore para encontrar la función/mensaje de dims mismatch existente

### Step 2: Validar dims en put
- **Archivos:** `vantadb-mcp/src/handlers/tools.rs` (o donde viva la validación)
- **Acción:** en el handler put, si el namespace tiene índice, validar dims del vector entrante; error claro si difiere
- **Verify:** `cargo check -p vantadb-mcp`
- **Estado:** ✅ DONE — en `memory_put` (tools.rs L214-233): tras parsear `vector`, si `index_vector_dim(storage)` devuelve `Some(expected)` y `vector.len() != expected` → `Ok(error_content(VantaError::DimensionMismatch { expected, got }.to_string()))` ANTES de construir el input y llamar `embedded.put`. Reutiliza el mismo helper + error que search (MCP-04). Índice vacío → `None` → acepta (define la dim). `cargo check -p vantadb-mcp` ✅.
