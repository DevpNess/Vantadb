## Fase 1 — Evidencia de Debugging (GATE — solo tipo Bug)

- **Repro:** `cargo nextest run -p vantadb --no-default-features --lib -E 'test(sync_to_mmap_preserves_data)'` → FAIL: panic `src/index/core.rs:321:62` ("reload mmap"). El archivo renombrado por `sync_to_mmap` (file.rs:132-144: copy → flush → drop → rename) queda con ceros porque `MmapMut::flush()` del shim es no-op (vfile_mmap.rs:131-133). Mismo patrón en `compact_layout` (archive.rs:95,135): tmp file se renombra sin el buffer.
- **Hipótesis:** el shim `MmapMut` guarda solo `AlignedBytes` (buffer RAM) y no el `File`; `flush()` no-op → los writes al buffer nunca llegan al disco antes del rename. Fix: el shim debe recordar el File y `flush()` = write-back (seek + write_all + flush).
- **1 variable controlada:** el ÚNICO cambio es la implementación de `flush`/`flush_async`/`flush_range` del shim + struct `MmapMut` (guardar File). Nada más cambia.
- **Test RED:** (a) nuevo unit test `shim_mmap_mut_flush_writes_buffer_to_disk` en vfile_mmap.rs (gated `not(feature="memmap2")`); (b) `test_compact_layout_disk_backed` en archive.rs se fortalece con reopen + verificación de bytes del vector (falla en shim build pre-fix, pasa post-fix).
