## Evidencia
- `vanta-cli server --http` (binario instalado vía cargo install / release) → `Error: CliError { msg: "HTTP server requires the 'server' feature. Rebuild with: cargo build --features server" }`
- `target\release\vanta-cli.exe` (build sin features extra) → mismo error
- `cargo build --release --features server` → compila ✅ y el server responde `/health` + `POST /api/v2/query` (VantaQL) ✅
- `Cargo.toml:97`: `default = ["cli", "arrow", "fjall", "roaring", "advanced-tokenizer", "memmap2", "fs2", "sysinfo", "rayon"]` — **no incluye `server`**
- `release-binaries-63.yml`: build con `ALLOC_FEATURES` (custom-allocator/jemalloc) — tampoco incluye server

## Contrato
"el binario publicado (cargo install / GitHub Release) soporta `vanta-cli server --http`; `vanta-cli server --http` arranca y `/health` responde OK; `cargo check --no-default-features --features server` compila"

## Investigation Notes
La feature `server` existe (`Cargo.toml:128-134`, habilita tokio/axum/tower_governor/tower-http). El binario publicado se construye sin ella. Opciones:
1. **Agregar `server` a `default`** — más simple, pero todos los usuarios compilan axum/tokio aunque no usen HTTP (costo de build/binary).
2. **Agregar `server` a la feature set del workflow de release** (`release-binaries-63.yml` y `release.yml` / cargo install docs) — los usuarios de HTTP obtienen el binario correcto, el costo de build solo para release.

Decisión recomendada: **opción 2** (release workflow) — mantener default lean; documentar en README que el binario de release incluye server. Pero VERIFICAR con webfetch/docs si cargo install compila default features (sí: cargo install usa default). El que instala via cargo install SIN --features server no tendrá HTTP — documentar en README: `cargo install vantadb-cli --features server` o que el release binario lo incluye.

**NO tocar** el código del server (funciona); solo la config de features/build.

## Decisión (Step 1 — ✅ REGISTRADA 2026-08-17)
**Opción 2: release workflow + README.** Validado contra cargo docs oficiales (doc.rust-lang.org/cargo/commands/cargo-install.html, sección Feature Selection): *"When no feature options are given, the `default` feature is activated"* → `cargo install vantadb-cli` compila solo default features (sin `server`). El build de release (`release-binaries-63.yml:111`) usaba `--features "$ALLOC_FEATURES"` (custom-allocator/jemalloc) — tampoco incluía `server`. Fix aplicado:
1. `release-binaries-63.yml` → vanta-cli se compila con `--features "server,$ALLOC_FEATURES"` (server + allocator; default queda lean). `release.yml` es release-plz (publish crates.io, no build) → sin cambios.
2. `README.md` + `README_ES.md` → nota de instalación: release binario incluye server; `cargo install --git ... --bin vanta-cli --features server` para HTTP en installs desde fuente.
