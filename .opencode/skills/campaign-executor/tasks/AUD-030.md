## Verificación (evidencia)
1. **Antes:** `on:` solo schedule `0 3 * * *` + workflow_dispatch; `permissions: contents: read`; ningún step llamaba `update-baseline` (el modo existía en `scripts/bench_regression.py` sin caller).
2. **Trigger PR agregado** con `paths` filter (benches/**, benchmarks/**, scripts/bench_regression.py, Cargo.toml) — solo PRs que tocan el sistema de bench pagan el gate; el resto no espera 2hrs de bench (respeta CI_POLICY two-tier).
3. **Auto-commit baseline:** step en job `analyze` — `python scripts/bench_regression.py update-baseline benchmark_report_criterion.json` + commit/push. `if: github.event_name == 'schedule' && steps.check_regression.outputs.has_regression != 'True'` → PRs jamás mutan el baseline del repo y un run con regresión nunca se hornea como baseline.
4. **`permissions.contents: write`** (antes read) — necesario para el push del baseline; PR runs corren con el scope de fork read-only por defecto de GitHub.
5. **Grep confirma** `steps.check_regression.outputs.has_regression` coincide con el `id: check_regression` existente (línea 159, output `has_regression` = `True`/`False`).
6. **YAML OK:** `yaml.safe_load` UTF-8 pasa.
