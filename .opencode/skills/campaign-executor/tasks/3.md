## Decisiones de diseño (verificadas contra el core)
1. **`VantaMemoryFilter` NO es `{op, items}`** — es `pub type VantaMemoryFilter = Vec<VantaMemoryFilterItem>` (src/sdk/types.rs:127). La nota del orquestador era incorrecta; el patrón wire correcto es el de Task 2 (`Vec<VantaMemoryFilterItem>`). No se crea un tipo TS `VantaMemoryFilter` (YAGNI): se usa `VantaMemoryFilterItem[]`, igual que `exportNamespace`.
2. **Trait method `&mut self` + write lock en manager** (no read lock): destructivo, consistente con `delete` (trait.rs:97, manager.rs:262-270). Write lock evita mutaciones concurrentes sobre la misma conexión durante el batch delete.
3. **TS SDK retorna `bigint`** (u64 → BigInt en wasm-bindgen; patrón `purgeExpired(): bigint` vanta.test.ts:609). Desktop wrapper (Tauri invoke) retorna `Promise<number>` (JSON number).
4. **Cache WASM:** `mark_cache_invalid()` tras delete_by_filter exitoso (mismo patrón que `purge_expired`, lib.rs:1213).
