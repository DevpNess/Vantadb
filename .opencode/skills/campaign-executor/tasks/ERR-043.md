# ERR-043 — `shrink_neighbors` clona el vector del nodo solo para usarlo como query

## Descripción

`shrink_neighbors` clonaba el vector del nodo (`n.vec_data.as_f32_slice().map(|s| s.to_vec())`)
únicamente para usarlo como query en el cálculo de distancia — un alloc O(vec_len) evitable
por shrink. Hot path de mantenimiento del grafo HNSW.

## Resolución

El fix ya estaba implementado y commiteado como `2a20b14a perf(ERR-043): borrow neighbor vector
in shrink instead of cloning` (ancestro de HEAD, 2026-08-10).

Cambio: se extrajo `compute_shrunk_neighbors` que lee el vector del nodo como **slice prestado**
(`let nb_v = n.vec_data.as_f32_slice()?;`) y lo pasa por referencia a `fast_similarity(nb_v, ...)`
(que acepta `&[f32]`). Se eliminó el `to_vec()` por shrink. Sin cambio de comportamiento: el mismo
`select_neighbors` canónico (tie-break id ascendente, AUD-014) produce el mismo set de sobrevivientes.

El guard de DashMap vive solo dentro del helper, de modo que el `get_mut` posterior del caller
sobre el mismo id nunca contiende (documentado en el doc-comment).
