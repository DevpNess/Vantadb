# CI-06 — Tests gate en release workflows

> Plan: `docs/plans/2026-08-12-ci-deuda.md` (Task 5)
> Estado: ⬜ PENDING
> Tipo: ci-cd (release pipelines) — scope vanta-lead
> Skills: ci-cd-and-automation, git-workflow-and-versioning

## Objetivo

`release-binaries-63.yml` y `release-npm-61.yml` son build-only: publican
binarios/paquetes sin correr tests. Agregar job `tests` a ambos y hacer que el
publish dependa de él (`needs: [tests]`), reusando la lógica del Fast Gate
existente (ci-rust-10.yml / ci-web-11.yml) para no duplicar config.

## Contrato (verificable)

- `release-binaries-63.yml`: job `tests` (cargo nextest, profile audit, mirror
  del job `test` de ci-rust-10.yml) y job `build` con `needs: [tests]`.
- `release-npm-61.yml`: job `tests` (npm test en vantadb-ts, precedido de
  build wasm pkg + npm install + npm run build) y job `publish-wasm` con
  `needs: [tests]` (publish-ts ya depende de publish-wasm → cadena completa).
- `actionlint` exit 0 sobre ambos workflows.
- Verificación mecánica: `actionlint .github/workflows/release-binaries-63.yml`
  y `actionlint .github/workflows/release-npm-61.yml` → exit 0.

## Impacto mapeado (Regla 0)

**Archivos a editar (completos leídos):**
- `.github/workflows/release-binaries-63.yml` (114 líneas) — job único `build`
  (matrix 5 targets), sin tests.
- `.github/workflows/release-npm-61.yml` (156 líneas) — jobs `publish-wasm` →
  `publish-ts` (`needs: [publish-wasm]`), sin tests.

**Referencias hacia dentro:** ninguna — los workflows son definiciones de
GitHub Actions; no hay código que los importe. Mencionados en
`docs/operations/CI_POLICY.md` y en el plan file (solo texto).

**Referencias hacia afuera (que usan los jobs editados):**
- `release-binaries-63.yml`: `actions/checkout@v4`,
  `actions-rust-lang/setup-rust-toolchain@166cdcf...`,
  `Swatinem/rust-cache@7e35be2...`.
- `release-npm-61.yml`: `actions/checkout@v4`, `actions/setup-node@v4`,
  `jetli/wasm-pack-action@0d096b0...`, `dtolnay/rust-toolchain@fa04a14...`,
  `actions/upload-artifact@ea165f8...`, `actions/download-artifact@d3f86a1...`.
- El job `tests` nuevo de binaries reusa `.github/actions/rust-setup`
  (composite action, leída completa — inputs: toolchain, components, swap-mb,
  install-nextest, install-system-deps).

**Dependencias de runtime del test npm** (verificadas en el repo):
- `vantadb-ts/src/vantadb.ts` importa `vantadb-wasm` → `file:../vantadb-wasm/pkg`
  → el test job DEBE construir el pkg wasm antes de `npm test`.
- Los tests vitest importan `../vantadb.js` (dist compilado) → `npm run build`
  previo requerido.
- `vantadb-ts/package.json` tiene `"test": "vitest run"`; lockfile existe
  (`vantadb-ts/package-lock.json`), `vantadb-node/package.json` existe.

**Dependencias del test nextest** (verificadas):
- Fast Gate (`ci-rust-10.yml` job `test`) corre `cargo nextest run --profile
  audit --features "cli,arrow,tls,opentelemetry"` + dataset GloVe cache/download.
- `.config/nextest.toml`: `profile.audit` hereda el default-filter de `default`,
  que excluye `benchmark_datasets`/`benchmark_internal`; tests con GloVe
  self-skip si el dataset falta. Se incluye el dataset igual (paridad con el
  gate probado; cache repo-wide lo hace barato).

**Veredicto de impacto:** aditivo. Se agregan jobs y una arista `needs`; no se
modifica el comportamiento de build/publish existente. No rompe otros
workflows ni código. No tocar archivos ajenos del worktree (src/sdk/...,
P2-7.md, ADR-019).
