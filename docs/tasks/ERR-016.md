# ERR-016 — Parser descarta WHERE/RANK silenciosamente (data loss en queries)

> Origen: `docs/Backlog.md:370` + `docs/reviews/errors-found.md:56`
> Prioridad: 🔴 Crítico · Esfuerzo: 🟢 Bajo · Tipo: Rust core bug (parser)

## Síntoma

En `src/parser/mod.rs`, `parse_query()` (línea 174) hace:

```rust
let (i, target_alias) = opt(ws(ident))(i)?;
```

Sin alias explícito en el query, `opt(ident)` consume `WHERE` / `RANK` / `FETCH` / `WITH` / `ROLE` como si fueran el alias opcional. El filtro se pierde: `FROM Person WHERE edad = "25"` → el `WHERE` se come como alias `"WHERE"`, `where_clause` queda `None`, y la query devuelve TODOS los nodos sin filtrar. **Data loss silencioso** (query ejecuta 200 OK, devuelve resultados completos sin el filtro pedido).

El test existente `test_parse_query_with_where_single` (línea 1043) documenta el workaround: "Must provide explicit alias before WHERE, otherwise opt(ident) consumes WHERE as alias" — usa `FROM Person p WHERE ...` con alias `p`. El comentario describe el BUG como requisito. Ese test NO cubre el caso roto `FROM Person WHERE edad = "25"`.

## Root cause

`opt(ws(ident))` no distingue palabras reservadas. El alias opcional debe rechazar keywords del lenguaje (`WHERE`, `RANK`, `FETCH`, `WITH`, `ROLE`, `AND`, `AS`, `DESC`, `TIPO`, `SIGUE`, `LIMIT`, `TIMEOUT`, `MATCH`, `FROM`, etc.) para que el parser continue a la cláusula real.

## Fix esperado (root-cause, no workaround)

El parser del alias opcional en `parse_query()` debe fallar al encontrarse con una keyword reservada, dejando el token para la cláusula que sigue. Técnica nom estándar: `verify` sobre `ident` con un set de keywords reservadas, o `alt((verify(ident, ...), fail))`. El alias por defecto `"target"` se conserva.

Requisitos:

1. `FROM Person WHERE edad = "25"` → `where_clause = Some([...])`, `target_alias == "target"`.
2. `FROM Person RANK BY score` → `rank_by = Some(...)`, `target_alias == "target"`.
3. `FROM Person p WHERE edad = "25"` (alias explícito) → sigue funcionando igual.
4. Query con alias legítimo que no colisiona con keywords sigue funcionando.
5. No romper ningún test existente (97 tests del módulo parser).
6. `test_parse_query_with_where_single` puede mejorar su comentario (la nota de workaround ya no aplica) si lo requieres, pero el test en sí pasa igual.

## Verificación

- `cargo check -p vantadb` ✅
- `cargo test -p vantadb --lib parser::tests` — todas pasan, y **añadir un test nuevo** `test_parse_query_where_without_alias` (o similar) probando `FROM Person WHERE edad = "25"` sin alias.
- `cargo fmt --check`

## Nota

Dejar los alias en español (`SIGUE`, `TIPO`, `ROLE`, `RANK BY`, `WITH TEMPERATURE`) tal como el parser existente los maneja — solo añadir la protección de keywords en el punto del alias opcional (y, si aplica, el mismo patrón en `parse_traversal` si tiene un `opt(ident)` análogo — revisar líneas 172-175).
