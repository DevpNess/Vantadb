# AUD-033 — Validar argumentos CLI de vantadb-server

## Objetivo

Que `vantadb-server` rechace flags desconocidos (ej. `--por 8080`) con un error claro y
exit code no-cero, en vez de ignorarlos silenciosamente y arrancar el servidor.
Invocaciones válidas (`-h`, `--help`, `--mcp`, sin args) siguen funcionando igual.

## Fase 1 — Evidencia de Debugging

- **Repro:** `cargo run -p vantadb-server -- --por 8080` → arranca el HTTP server
  (exit 0); el flag desconocido se ignora sin aviso.
- **Hipótesis (root cause):** `main()` (src/main.rs) escanea argv con
  `args.iter().any(...)` y solo comprueba `-h`/`--help` y `--mcp`; cualquier otro
  argumento se descarta silenciosamente. No existe validación de args desconocidos.
- **1 variable:** el resultado de `validate_args(&args)` (nueva fn pura).
- **RED:** `cargo nextest run --profile audit -p vantadb-server --build-jobs 2 -E 'binary(cli_args)'`
  → falla `unknown_flag_fails_with_error` (el binario actual sale con 0).

## Fase 2 — Implementación (Contract)

- `src/main.rs`:
  - `fn is_known_flag(arg: &str) -> bool` — `matches!(arg, "-h" | "--help" | "--mcp")`.
  - `fn validate_args(args: &[String]) -> Result<(), String>` — Err con el primer arg desconocido.
  - En `main()`, después del check de help: si `Err(unknown)` →
    `eprintln!("error: unrecognized argument '{unknown}'")` +
    `eprintln!("Run with --help for usage.")` + `std::process::exit(2)`.
  - Se preserva la precedencia del help y el texto de `print_help()` intacto.
- `tests/cli_args.rs` (nuevo): tests de proceso vía `env!("CARGO_BIN_EXE_vantadb-server")`
  con helper `output_with_timeout` (evita colgarse si el binario vuelve a bloquearse).
- Unit tests `#[cfg(test)]` en main.rs para `validate_args` (Ok: vacío/`--mcp`/`-h`/`--help`;
  Err: `--por`, `--por 8080`, `8080`, `--mcp --bogus`; primer desconocido gana).
