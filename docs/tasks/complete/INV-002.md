## Investigation Notes
- **Problema (del backlog):** el reporte de RAM mezcla core RAM, index RAM, page cache, mmap e ingest buffers en una sola cifra. Audit: "hasta que arregles la telemetría, no hables de eficiencia de memoria".
- **Hallazgos de codegraph (2026-07-30):**
  - Los gauges prometheus YA existen en `src/metrics/core/registry.rs`: `PROCESS_RSS_BYTES`, `PROCESS_VIRTUAL_BYTES`, `HNSW_NODES_COUNT`, `HNSW_LOGICAL_BYTES`, `MMAP_RESIDENT_BYTES`, `VOLATILE_CACHE_ENTRIES`, `VOLATILE_CACHE_CAP_BYTES`, `JEMALLOC_*` (6 gauges). Están detrás de `feature = "prometheus"`.
  - El sampler en `src/metrics/core/mod.rs` actualiza `LAST_PROCESS_RSS_BYTES` con fallback a sysinfo (líneas 374-462).
  - `src/memory_governor.rs` tiene un `MemoryGovernor` con `used_bytes` atómico (ingest accounting) pero NO está conectado a las métricas expuestas.
  - `src/cache_warmer.rs::metrics()` (línea 172) tiene `#[allow(dead_code)]` con nota ponytail: "a periodic metrics sampler should call this from the engine's tick loop" — el sampler periódico no existe aún.
  - HISTORIAL: `DISC-05` (progreso línea 1238) "Fix telemetría de memoria (~225 GB falsos en 34 GB)" marcado ✅ pero "pendiente reverificación formal". `memory_telemetry` test excluido del fast gate (180s, va a heavy_certification.yml).
- **Ambigüedad pendiente de validación web (el backlog propone `tracing::metrics` + labels):** el workspace usa el crate `prometheus` directo, no el ecosistema `metrics`/`metrics-tracing`. El sub-agente DEBE validar contra la doc oficial del crate `prometheus` (labels en `IntGaugeVec`) o `metrics` + `metrics-exporter-prometheus` antes de elegir el mecanismo de labels. Web search falló con rate-limit el 2026-07-30 — validar al ejecutar.
