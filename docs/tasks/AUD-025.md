# AUD-025 — BM25 hot path: allocaciones por posting en lexical_search

## DISCOVERY

- **Backlog:** docs/Backlog.md — finding de auditoría performance: `src/sdk/search/mod.rs:383-448` (hot path de BM25 en `lexical_search`) hace 2 allocaciones por posting (key + token) y re-fetch/clone de doc_stats por token.
- **Tipo:** perf (hot path optimization)
- **Archivos clave:** `src/sdk/search/mod.rs:384-448`, `src/text_index.rs:547,565`, `src/sdk/search/phrase.rs:13,28`

### Análisis del hallazgo

El loop de postings de `lexical_search` (líneas 389-450) itera `for token in query_plan.terms` (consumo por valor → `token.clone()` en L448) y por cada posting:

1. **`posting_record_key` (text_index.rs:565)** — construye un `String` nuevo por posting (`String::from_utf8(key_bytes.to_vec())`) para consultar `doc_stats_cache` keyed por `String`.
2. **`doc_stats_cache: BTreeMap<String, TextDocStats>`** — el hit devuelve `stats.clone()` (copia el struct por posting); el miss re-clona `record_key.clone()` + `stats.clone()`.
3. **`candidate_positions: BTreeMap<u128, BTreeMap<String, Vec<u32>>>`** — `insert(token.clone(), ...)` clona el token (String) por posting.

Firma actual `posting_record_key(namespace, token, index_key) -> Option<String>` tiene **1 solo caller** (mod.rs:411) → re-firma segura.

Verificado con codegraph + lecturas on-disk:
- `posting_record_key` — grep repo-wide: 2 matches (def text_index.rs:565, call search/mod.rs:411). ✅ cambio de firma seguro.
- `text_positions_match_phrases` — 2 callers: text_index.rs:516 (`BTreeMap<String,_>`), search/mod.rs:464 (`BTreeMap<&str,_>` tras el fix). Tests phrase.rs:136-182 usan `BTreeMap<String,_>` → siguen compilando.
- `load_text_doc_stats(engine, namespace, key: &str) -> Result<Option<TextDocStats>>` (impl_text_index.rs:211) — toma `&str` ✓.
- Relación 1:1 `posting.node_id` ↔ record (verificado por el guard de mismatch L428-432) → cachear por `u128 node_id` es correcto y conserva el error de mismatch en el miss.
- `posting_prefix(namespace, token) -> Vec<u8>` (text_index.rs:547) ya se construye por token en mod.rs:399 (usado para el scan) → se reusa para el strip, cero alloc extra.
- `&str: AsRef<str> + Ord` ✓ (blanket `impl<T: ?Sized> AsRef<T> for &T`); `String: AsRef<str> + Ord` ✓.

## EJECUCIÓN

1. **text_index.rs:565** — re-firmar `posting_record_key` a `pub(crate) fn posting_record_key<'a>(prefix: &[u8], index_key: &'a [u8]) -> Option<&'a str>` — `strip_prefix(prefix)?` + `std::str::from_utf8(...).ok()`; borrado zero-alloc, conserva el skip por UTF-8 inválido.
2. **phrase.rs:13,28** — genericizar `text_positions_match_phrases`/`text_positions_match_phrase` sobre `K: AsRef<str> + Ord`; reemplazar `term_positions.get(token)` por scan lineal `iter().find(|(k, _)| k.as_ref() == token)` (mapas por-doc diminutos). Callers (`String`, `&str`) y tests compilan igual.
3. **search/mod.rs loop** — `for token in &query_plan.terms` (borrow); `candidate_positions: BTreeMap<u128, BTreeMap<&str, Vec<u32>>>` con `insert(token.as_str(), posting.positions)`; `doc_stats_cache: BTreeMap<u128, TextDocStats>` keyed por `posting.node_id` — hit devuelve `stats.doc_len` (u32 Copy, sin clone), miss: fetch con `record_key` (&str), verificar `stats.node_id == posting.node_id` (mismatch → `Err(VantaError::SearchError(...))`), `insert(posting.node_id, stats)`, releer `doc_len` de la cache. `posting_record_key(&prefix, &posting_key)` reusa el prefix del scan.
