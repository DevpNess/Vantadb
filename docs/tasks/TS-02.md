## Fase 1 — Evidencia de Debugging (GATE — solo tipo Bug)

- **Repro:** `private _native<T>(method, fn) { try { return fn(); } catch(e){ throw wrapNativeError(e, method); } }` — bare `fn()` retorna Promise rechazada; el `catch` solo ve throws síncronos, la rejection async escapa sin envolver y el caller recibe error crudo del binding en vez de `VantaError(code=NATIVE_ERROR)`
- **Hipótesis:** falta `await` dentro del `try` para que el `catch` observe tanto throws síncronos como rejections asíncronas (TS-02 descripción: `async`, `try { return await fn(); } catch`)
- **1 variable controlada:** una sola edición: cambiar `_native` a `private async _native<T>(method: string, fn: () => Promise<T> | T): Promise<T> { try { return await fn(); } catch(e){ throw wrapNativeError(e, method);} }` — el `normalizeMetadataForNative` del diff es corrección de tipado adicional validada por tsc, pero la variable del bug es solo el await
- **Test RED:** `vantadb-ts/src/__tests__/native-error.test.ts` — test "wraps an ASYNC rejection" hace `makeDbWith({ get: () => Promise.reject(new Error("engine panicked")) })` y `await expect(db.get(...)).rejects.toBeInstanceOf(VantaError)` con `code: "NATIVE_ERROR"`. Antes del fix: ❌ (recibe Error crudo). Después: ✅ (3 tests pasan). Test usa fake inner para no requerir binary .node
