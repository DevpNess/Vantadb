## Investigation Notes
El prune en `src/index/graph.rs:963-978` re-implementa la selección top-M que `select_neighbors` (search.rs:451) ya hace. Dos problemas:
1. **Drift de tie-break**: `select_neighbors` usa `NodeSimMin::Ord` (desempata por node id ASCENDENTE, determinístico). El nuevo código ordena `sort_unstable_by(total_cmp_sim(b.0, a.0))` puro → ties con sim igual en orden arbitrario → resultados no reproducibles entre paths (add en graph.rs:722/869 vs shrink).
2. **Duplicación**: dos copias de la misma lógica divergirán más.

Root cause (audit Phase 5): `select_neighbors` no soporta el predicado extra "no evictar si es last-inbound" → el autor re-implementó inline.

Fix de raíz (preferido): extender `select_neighbors` con un predicado opcional `should_keep: impl Fn(u128) -> bool` (post-filtro: no evictar last-inbound) y reusar en prune. Mantener tie-break `NodeSimMin::Ord` en el camino único.
Fix mínimo (si el de raíz es muy invasivo): en graph.rs:970 usar el mismo comparador que `NodeSimMin` (desempate por id ascendente `a.1.cmp(&b.1)`) — pero NO dejar la duplicación; el de raíz es el correcto.

**NO tocar la cota de listas over-capacity (es AUD-015, fuera de alcance).** Solo deduplicación + tie-break.
