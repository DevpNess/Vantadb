## DISCOVERY (2026-08-11, lead)
- `cargo test -p vantadb-server --test server` → **6 pass / 9 FAIL** de 15.
- **Causa raíz de los 9 fallos:** desalineación con ERR-027 (commit `6b3dce25`,
  "fix(http): return 4xx/5xx on query error"). Los tests mandan `{"query":"test"}`
  esperando 200; post-ERR-027, un query no parseable → `StatusCode::BAD_REQUEST`
  (`src/cli_server.rs:1367-1371`, `query_error_response` :545-561). Antes el error se
  tragaba con 200.
- **Auth middleware** (`src/cli_server.rs:345+`): `/health` público; sin api_key → allow
  all (dev mode, :368-375); con api_key → Bearer token `ct_eq` (:392-404). Rate-limit
  governor :150-166 (AUD-021 fail-closed).
- **RBAC:** `src/rbac.rs` (`Permission` Read/Write/Delete/Admin/NamespaceRead/
  NamespaceWrite; `Rbac` con roles) — `#![allow(dead_code)]`, **NO conectado al
  middleware HTTP**. `ServerState` tiene `rbac: Arc<Rbac>` + `token_role_map`
  (:278-279, :132-139) pero `auth_middleware` nunca consulta permisos.
- Test helpers: `post_query` usa `{"query":"test"}` (:58-72) — ese body NO es IQL válido.

## Decisión de alcance (lead)
1. **Arreglar los 9 tests rotos** — root-cause: el helper `post_query` debe mandar un
   query válido (ej. `"SELECT 1"` — mismo usado en :1197) o el test debe esperar el
   status correcto. NO bajar la expectativa de ERR-027 (el 4xx es comportamiento
   correcto y ya está testeado en cli_server.rs:1342).
2. **Añadir tests HTTP de RBAC** — REQUIERE primero integrar RBAC al middleware
   (`auth_middleware` hoy solo valida api_key; no consulta `token_role_map`/`rbac`).
   Evalúa la integración mínima: mapear token→rol vía `token_role_map`, validar
   permiso por ruta (query = Read/Write según método). Si la integración crece mucho,
   detente y documenta el tradeoff: RBAC HTTP es una FEATURE nueva, no un test.
3. **No tocar** `vantadb-server/tests/e2e.rs` ni benchmarks salvo que fallen por lo mismo.
