## Evidencia
1. **CLI `put` no tiene `--metadata`**: `vanta-cli put` acepta solo payload/vector — imposible escribir metadata desde CLI (el SDK Python y MCP sí pueden)
2. **Filtros CLI solo aplican a metadata de usuario**: `count --filter '{"__vanta_x": {...}}'` devuelve 0 — los campos internos `__vanta_*` no son filtrables por CLI (probablemente correcto como límite, requiere documentación)
3. **TTL no vía MCP**: `expires_at_ms` se ignora en MCP put (cubierto por AUD-045 — si AUD-045 lo resuelve, esta parte de AUD-051 queda como verificación)

## Contrato
"CLI `put --metadata '{"k":"v"}'` funcional y documentado; doc CLI aclara que los filtros aplican solo a metadata de usuario (campos `__vanta_*` no filtrables); TTL vía MCP verificado (si AUD-045 lo cubrió, marcar sub-item como verificado)"

## Investigation Notes
Alcance:
1. **`--metadata` en CLI put**: flag `--metadata <JSON>` que parsea y pasa al record. **DECISIÓN: FIX** (additive, contrato lo exige). El CLI construye `UnifiedNode` directo vía `open_database` — insertar metadata como campos relacionales (mismo mecanismo que `memory_record_to_node_owned`), convirtiendo con `json_to_vanta_value` + validación de prefix `__vanta_` (el CLI no pasa por `validate_metadata` del SDK; paridad obligatoria). `engine.insert` persiste el nodo completo y `memory_record_from_node` devuelve los campos no-reservados como metadata → get/list/search la ven.
2. **Filtros internos**: **DECISIÓN: DOCUMENTAR** (no implementar filtrado de `__vanta_*`) — es decisión de scope, no un bug. Evidencia en código: `memory_record_from_node` (mod.rs L301-308) remueve los campos `__vanta_*` de `record.metadata`; `matches_memory_filters`/`matches_advanced_filters` (mod.rs L476-499) comparan SOLO contra `record.metadata` → un filtro `{"__vanta_x": ...}` devuelve 0 SIEMPRE. El $0 actual ya es el bloqueo fail-safe; rechazar con error rompería scripts existentes. Documentar en CONFIGURATION.md.
3. **TTL MCP**: **DECISIÓN: cubierto por AUD-045 (pendiente)** — `tools.rs:223-225` aún tiene `ttl_ms: None`; AUD-045 task file PENDING. NO tocar tools.rs (plan L29 protege el archivo para AUD-045/046/048/050). Sub-item marcado como verificación pendiente de AUD-045.
