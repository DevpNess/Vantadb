  - Docs Tauri v2: `https://v2.tauri.app/plugin/deep-linking/`
- **Hallazgos clave (textuales de las fuentes):**
  1. *"On Linux and Windows deep links are delivered as a command line argument to a new app process. The deep link plugin has integration with the single instance plugin if you prefer having a unique app instance receiving the events."* → **en Windows es OBLIGATORIO** `tauri-plugin-single-instance` con feature `deep-link` para recibir el evento en runtime. Config de dep: `tauri-plugin-single-instance = { version = "2.0.0", features = ["deep-link"] }`.
  2. *"Then configure the single instance plugin which should always be the first plugin you register"* → single-instance se registra PRIMERO, antes de deep-link.
  3. Config `tauri.conf.json`: `{ "plugins": { "deep-link": { "desktop": { "schemes": ["vanta"] } } } }`
  4. Registro en dev/test sin instalar: `app.deep_link().register_all()?` con `#[cfg(any(windows, target_os = "linux"))]` en setup (sección Testing de la doc).
  5. URL inicial (app arrancada por el link): `app.deep_link().get_current()?` en `setup` (Rust) / `getCurrent()` (JS). *"getCurrent's return value will also get updated every time onOpenUrl gets triggered"*.
  6. Test manual Windows: `start vanta://...` (sección Testing → Windows).
  7. Caution oficial: *"The user could trigger a fake deep link manually by including the URL as argument... you should still check if the URL matches the format you expect"* → el handler frontend filtra `vanta://` y parsea con formato estricto.
  8. Permisos: el comando `get_current` JS necesita `deep-link:default`; **no lo usamos** (sin guest binding npm) — el manejo es Rust-side: comando propio `vanta_deep_link_take` + evento propio `vanta-deep-link` (no depende del guest binding; `core:event:default` ya incluido en `core:default` de capabilities).
