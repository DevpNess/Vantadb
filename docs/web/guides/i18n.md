# i18n System

Custom `LanguageProvider` context (NOT next-intl). Two languages: Spanish (`"es"`, default) and English (`"en"`). The `next-intl` npm package is installed but never imported.

## Architecture

```
layout.tsx
└── LanguageProvider (wraps entire app)
    └── useLanguage() hook → { lang, setLang, t(key, params?) }
```

The `t()` function signature: `(key: string, params?: Record<string, string>) => string`. Single-brace interpolation via `.replace()` — `t("footer.copyright", { year: "2026" })` replaces `{year}` in the dictionary value.

## Dictionary Structure

- **File:** `src/lib/dictionaries.ts` (2993 lines)
- **Structure:** Flat `Record<string, string>` per language (NOT nested)
- **Keys:** 1,228 per language, namespace-dot convention: `common.copied`, `nav.platform`, `hero.subheadStrong`, `footer.copyright`, `changelog.noResults`, `caseStudiesData.0.title`, etc.
- **Exported as:** `dictionaries: Record<Lang, Record<string, string>>`
- **Sections (in order):** Common, Nav, Hero, Metrics, Features, Terminal, Architecture, Playground, Boundary, Use Cases, Ecosystem, Tutorials, Changelog, FAQ, CTA, Pricing, Why, Trust, Benchmarks, Docs, Engine, Solutions, Search Semantics, Security, Cost, Maintenance, About, View titles, Toast, etc.

## Language Detection & Persistence

```ts
// On mount:
// 1. Check localStorage("vantadb-lang")
// 2. Fallback to navigator.language (first 2 chars, anything not "en" → "es")
// 3. Default to "es"
// On setLang(): writes to localStorage + updates document.documentElement.lang
```

## SSR Behavior

- Server renders with `"es"` default
- Client-side effect syncs to stored/detected language after mount
- Guaranteed double render on first paint

## Known Issues

1. **`<html lang="es">` hardcoded** — Root layout.tsx has `<html lang="es" suppressHydrationWarning>`. LanguageProvider updates `document.documentElement.lang` client-side, but SSR always says `"es"`. Affects SEO and screen reader language.
2. **8 keys with double-brace mismatch** — Values like `"Sin resultados para \"{{query}}\""` use `{{}}` but `t()` only handles single braces `{}`. The replace partially works but leaves stray `{` characters. Keys affected: `changelog.noResults`, `faq.questionsCount`, `tutorials.noResults`, `tutorials.steps` (in both ES and EN).
3. **36 duplicated `tt()` helpers** — Every file that needs fallback text copies the same `const tt = (key, fallback) => { const v = t(key); return v === key ? fallback : v; }` pattern inline.
4. **No type safety** — Keys are plain strings (`t("typo.key")` compiles silently and returns `"typo.key"` as fallback).
5. **Unused `mounted` state** — `const [mounted, setMounted] = useState(false)` is set but never read.
6. **Language detection bias** — Only `"en"` gets English; German, French, Japanese, etc. all get Spanish.
7. **Consumer count:** 48 files import `useLanguage` (20 pages + 27 components + 1 layout).

## How to Add a New Key

1. Add to BOTH `es` and `en` objects in `dictionaries.ts`
2. Use single braces `{paramName}` for interpolated values
3. Use `t("namespace.key")` in code
4. If you need a fallback, use the `tt()` pattern
