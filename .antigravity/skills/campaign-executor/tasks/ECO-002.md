# ECO-002: Fix --no-verify contradiction in AGENTS.md (C3)

## Type
Documentation — rule contradiction

## Problem
`.antigravity/AGENTS.md` contiene dos reglas directamente contradictorias sobre `git push --no-verify`:

- **Línea 824** (Regla 1 — Pre-push Gate Estricto): *"Prohibido `--no-verify`: si el pre-commit o pre-push hook falla, NO se puede usar `--no-verify` para saltarlo. `--no-verify` solo se permite si el usuario lo ordena explícitamente."*
- **Línea 967** (Regla 7 — Release Workflow / Pre-push Gate): *"usar `git push --no-verify` SOLO si el cambio es trivial y CI lo va a validar igual."*

La Regla B contradice directamente la tabla anti-racionalización de la Regla A, que explícitamente dice que "porque es un cambio chico" NO es excusa válida.

## Investigation Notes (2026-07-23)
- La Regla A (línea 824) es la autoridad — es una regla fundamental del Development Protocol
- La Regla B (línea 967) es un **huérfano** — ningún archivo, comando, agente, prompt o skill depende de ella
- El escape hatch ya existe: "si el usuario lo ordena explícitamente" (línea 824)
- Los hooks de git (`.git/hooks/pre-push`, `.git/hooks/pre-commit`) mencionan `--no-verify` como información técnica factual — NO necesitan cambio
- `docs/references/troubleshooting.md` línea 191: documenta `git commit --no-verify` como comando existente — no necesita cambio
- `statewright/.github/workflows/release.yml`: usa `cargo publish --no-verify` (flag de Cargo, NO de git) — completamente diferente
- Ver reporte completo de investigación en sesión C3

## Contract
`git push --no-verify` solo se permite cuando el usuario lo ordena explícitamente. El agente nunca debe sugerirlo ni usarlo por iniciativa propia.
