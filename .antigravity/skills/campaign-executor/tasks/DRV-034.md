## Descripción
Cada método público de la clase `VantaDB` en `vantadb-ts/src/vantadb.ts` contiene un bloque try-catch idéntico para capturar y transformar errores de WASM. Con 76+ métodos, esto genera ~300 líneas de código repetido sin valor añadido.

| Dirección | Módulos |
|-----------|---------|
| Callers | Usuarios del SDK TypeScript (externos) |
| Callees | `vantadb-ts/src/vantadb.ts`, `vantadb-ts/src/types.ts` |
| Implicaciones | API pública no cambia. Solo la implementación interna de manejo de errores. |
| Riesgo | Bajo — tipo de retorno y comportamiento observable idéntico |

## Contrato
"`npx tsc --noEmit` en `vantadb-ts/` pasa sin errores, y el patrón de error wrapping es idéntico antes y después del refactor"

## Herramientas necesarias
- `npx tsc --noEmit`

## Steps

### Step 1 — Discovery
- Conteo real: **38 bloques** try-catch (no 76 como indicaba el backlog — el archivo tiene 1021L).
- Patrón uniforme: `try { return this.inner.X(...); } catch(e) { throw wrapWasmError(e, "X"); }`
- `close()` preservado con `try/finally` — tiene side-effect crítico en `_closed`.
- Hallazgo colateral: `reindex_hnsw_from_text` no existe en el WASM instalado — se marcó con error explícito.
- **Estado:** ✅ COMPLETED

### Step 2 — Implementar helper `_wasm<T>(method, fn): T`
- Añadido método privado genérico en la clase `VantaDB`.
- Refactorizados los 35 bloques idénticos en métodos de instancia con `_wasm()`.
- 3 factory methods estáticos (`connect`, `create`, `open`) conservan su try-catch (no tienen `this`).
- **Estado:** ✅ COMPLETED

### Step 3 — Verificación
- `npx tsc --noEmit` ✅ 0 errores, 0 warnings.
- **Estado:** ✅ COMPLETED
