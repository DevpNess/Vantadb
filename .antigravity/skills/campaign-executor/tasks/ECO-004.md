# ECO-004: Add server-level health check to campaign-server.mjs (H5)

## Type
Enhancement — MCP server resilience

## Problem
`campaign-server.mjs` expone `campaign_health_status` pero este tool solo verifica **métricas de tasks** (total, completed, failed, stalled) — NO verifica la salud del servidor mismo. Si el MCP server falla:
- No hay liveness check
- No hay auto-restart
- No hay fallback/graceful degradation
- No hay log de diagnóstico de la falla
- `server.connect()` no tiene try/catch

## Investigation Notes (2026-07-23)
- `campaign_health_status` (líneas 853-860) llama a `getHealth(PROJECT_ROOT)` que devuelve task metrics. No verifica server liveness.
- El servidor arranca en 3 líneas (1218-1220) sin try/catch en `server.connect()`
- No hay `process.on('uncaughtException')` ni `process.on('unhandledRejection')`
- 31 tools MCP definidos, ~18 referenciados externamente en prompts/agentes
- Si el servidor falla: **TODO el sistema de pipeline se detiene** — 7 agentes, 4 prompts, 4 comandos, C0 state machine
- 0 fallback paths documentados en ningún prompt o agente
- Solo `opencode.jsonc` tiene `"enabled": true` — no hay restart policy configurable
- Ver reporte completo de investigación en sesión H5+H6

## Contract
`campaign_health_status` verifica que el servidor MCP esté vivo (no solo métricas de tasks). El servidor tiene manejo básico de errores de conexión.

## Herramientas
- read, edit

## Steps
### Step 1: Modificar `campaign_health_status` para incluir server liveness
- **Archivos:** `.antigravity/task-system/mcp/campaign-server.mjs` (alrededor de líneas 853-860)
- **Acción:** Agregar `serverLiveness: true` al response — tool verifica que puede responder.
  Opcional: agregar uptime (timestamp de inicio del server).
- **Verify:** El tool devuelve `{ serverLiveness: true, ... }` en vez de solo métricas
- **Estado:** ⬜ PENDING

### Step 2: Agregar error handler a `server.connect()`
- **Archivos:** `.antigravity/task-system/mcp/campaign-server.mjs` (alrededor de líneas 1218-1220)
- **Acción:** Envolver `await server.connect(transport)` en try/catch con `console.error` diagnóstico
  Opcional: agregar `process.on('uncaughtException')` y `process.on('unhandledRejection')` con información diagnóstica a stderr
- **Verify:** El servidor captura errores de conexión y los muestra por stderr en vez de crash silencioso
- **Estado:** ⬜ PENDING

### Step 3: Verify con prueba manual
- **Acción:** Ejecutar `node ".antigravity/task-system/mcp/campaign-server.mjs"` y verificar que arranca y responde
- **Verify:** El server inicia sin errores, `campaign_health_status` devuelve `serverLiveness: true`
- **Estado:** ⬜ PENDING

## Notas
