# DRV-007: Data race en `filter_field()` (scalar_index sin lock)

**Status:** ✅ COMPLETED (Gate-check Jul 24)
**Type:** bug (data race audit)
**Priority:** 🟡 Medium

## Description

Original: `filter_field()` accede `scalar_index` sin adquirir `nodes.read()`. Mutaciones en `insert()`/`delete()`/`update()` modifican `scalar_index` bajo `nodes.write()`, pero `filter_field` lo lee sin protección.

## Gate-check Result

✅ **ALREADY FIXED at architectural level.** `ScalarIndex` usa `DashMap` — internamente sharded con locks propios, concurrentemente seguro. No hay undefined behavior ni data race real en Rust memory model. La variable `_nodes` (L379) es dead code que adquiere y suelta al instante. El riesgo lógico (lectura stale) es inherente a sistemas concurrentes — no es un bug.

**Archivos verificados:**
- `src/engine.rs:378-381` — `filter_field()` con `_nodes` binding muerto + `DashMap.lookup()`
- `src/scalar_index.rs:1-67` — `ScalarIndex` implementado con `DashMap`

**Ponytail:** YAGNI — no tocar código muerto que no causa problemas.
